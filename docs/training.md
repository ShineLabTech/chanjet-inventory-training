# 从一次查询理解场景、节点与接口

场景：同事知道要找外箱物料，希望通过 AI 找到存货编码。

业务对象是物料主数据。流程从用户提出查询条件开始，到返回可核对的编码、名称、状态和查询时间结束。采购审批、库存计算、同步写表属于其他流程。

| 节点 | 输入 | 输出与完成标准 |
|---|---|---|
| 确定查询条件 | 用户描述 | 分类、关键词、展示条数明确 |
| 取得物料数据 | 分类、受控只读身份 | 请求成功，返回范围和数据完整性通过检查 |
| 筛选并展示 | 物料集合、关键词 | 编码保留前导零，展示匹配数量、时间与请求编号 |
| 处理失败 | 错误码与失败阶段 | 明确失败原因和承接人，不把失败当作空结果 |

查询接口：`GET /api/v1/erp/chanjet/inventory`，多分类用重复的 `class_code` 参数。授权、上游分页由公司接口服务处理；调用者负责正确提供范围并校验返回值。公司 API 查询成功后，CLI 还需完成筛选和展示。

“取得物料数据”节点卡：

| 字段 | 内容 |
|---|---|
| Input | 合法分类、具有 inventory:read 的调用身份 |
| Output | 已校验的物料集合，或明确失败信息 |
| Owner | 客户端维护人负责调用与校验，接口维护人负责查询服务 |
| SLA | 客户端单次请求 60 秒超时；这是技术超时，不是业务响应承诺 |
| Gate | 成功响应、范围一致、计数一致、ID 唯一、字段类型正确 |
| Archive | 查询时间、请求编号、运行链接；不记录 Key |

练习顺序：

1. 让 AI 查询外箱编码，找到对应运行记录。
2. 改为查询原料，按编码的一部分或名称筛选。
3. 阅读 `company-chanjet.mjs`，指出输入校验与返回校验的位置。
4. 让 AI 加一个“只显示正常物料”的选项，用虚构数据测试停用筛选。
5. 新建分支和 PR，说明改动、输入与预期结果，请另一位同学 Review。

互审时检查：缺 Key 有没有明确报错？空结果有没有被如实呈现？编码 `00123` 有没有变成 `123`？查询失败有没有被说成“没有物料”？

本仓库只抽取畅捷通项目中用于查询的客户端，不包含生产服务端、同步任务、授权秘密或历史业务快照。项目完整案例说明见[公司 Handbook 的畅捷通集成案例](https://github.com/ShineLabTech/ShineLabTech-vibecoding-handbook/blob/main/docs/cases/chanjet-feishu-integration.md)。
